# Chặng 1 — ST STM32H753ZI / NUCLEO-H753ZI (Arm Cortex-M7)

**Đích:** tự giải thích Cortex-M7 + memory/cache/bus, khởi động STM32, clock/reset, NVIC, DMA và tối thiểu GPIO–timer–UART; viết driver GPIO nhỏ qua register/CMSIS, so sánh với HAL/LL và chứng minh bằng unit + board test. Board [NUCLEO-H753ZI](https://www.st.com/en/evaluation-tools/nucleo-h753zi.html) đang được ST liệt kê active, có ST-LINK trên board; không mua nhầm NUCLEO-H743ZI đời cũ đã obsolete. Nếu dùng board khác, thay `TARGET.md`, pin/clock/test plan tương ứng.

## Đọc tài liệu đúng thứ tự, trước khi làm quiz/code

1. [Trang tài liệu STM32H743/753](https://www.st.com/en/microcontrollers-microprocessors/stm32h743-753/documentation.html): lấy **datasheet DS12117, reference manual RM0433, programming manual PM0253, errata ES0392** đúng revision; ghi ngày/version vào `TARGET.md`.
2. [Board NUCLEO-H753ZI](https://www.st.com/en/evaluation-tools/nucleo-h753zi.html): board manual UM2407, schematic MB1364, LED/button/ST-LINK wiring; **không đoán pin LED theo ví dụ board khác**.
3. Trong RM0433/PM0253: CPU exception, vector table, NVIC, cache/MPU; memory/AXI/AHB/APB; RCC/PWR/reset; boot option; GPIO/AF; EXTI; timer; USART; DMA. Datasheet cho voltage/pin/alternate functions; errata cho silicon limitation.
4. Đọc startup file/linker script do STM32CubeIDE tạo và [CMSIS/Core](https://arm-software.github.io/CMSIS_6/latest/Core/index.html): reset handler, stack pointer, `.data/.bss`, `SystemInit`, `main`.

**Register notebook mẫu phải tự điền:** RCC clock enable của GPIO port đã chọn; GPIO `MODER`, `OTYPER`, `PUPDR`, `AFR`, `IDR`, `ODR`, `BSRR`; EXTI line/mux; NVIC enable/priority; timer prescaler/ARR/interrupt status. Mỗi dòng ghi base+offset, access/reset, bit/side effect, clock dependency, chapter và chip revision. Không copy địa chỉ ESP32.

Sau bốn phần lý thuyết, đọc [bản đồ kiến trúc](08_SO_SANH_KIEN_TRUC.md), làm câu **1–8** của [quiz](09_QUIZ_DA_CHIP.md), rồi đối chiếu [đáp án](10_DAP_AN_QUIZ_DA_CHIP.md). Chỉ sau đó mới viết driver.

## Lịch 8 tuần (lý thuyết → quiz → code → test)

| Tuần | Học/làm theo thứ tự | Bằng chứng |
|---:|---|---|
| 1 | Đọc datasheet/board schematic; vẽ Cortex-M7, memory, bus, cache | Sơ đồ + nguồn từng khối |
| 2 | Clock/RCC/reset/boot/linker/Flash/RAM; phân biệt SRAM cho CPU và DMA | Boot flow, memory map, ELF/map/size |
| 3 | GPIO/AF, EXTI/NVIC, timer, USART, DMA/cache coherency | Register notebook và timing diagram |
| 4 | Viết SRS, ADR, design, test cases; làm **quiz lý thuyết sau khi đọc đủ** (≥85% và giải thích câu sai) | Review gate A–F của [quy trình chung](01_COMMON_A_TO_Z_VMODEL.md) |
| 5 | Build minimal firmware bằng STM32CubeIDE, sau đó driver GPIO mức register/CMSIS; không dùng HAL GPIO đồng thời trên cùng pin | Build/ELF/map, code review, API Doxygen |
| 6 | Timer periodic + UART log; EXTI button→event/state machine; unit fake-register/state test | Host unit log, target integration log |
| 7 | DMA hoặc peripheral transfer có buffer ownership; thử cache maintenance theo tài liệu, không suy từ `volatile` | Before/after test + waveform/serial evidence |
| 8 | Watchdog/reset/fault cases, timing + stack/RAM measurement, traceability/release review | Test report + gaps/errata disposition |

## Bài lab và acceptance criteria

- `STM-REQ-01`: LED trên board theo chu kỳ đặt trong SRS; **timer**, không dùng vòng bận làm clock. Pass khi đo được chu kỳ và jitter trong ngưỡng do bạn định trước.
- `STM-REQ-02`: button tạo event qua EXTI; debounce là state machine, ISR không xử lý dài. Pass khi test press/release/bounce và không double event ngoài chính sách.
- `STM-REQ-03`: UART báo trạng thái/lỗi, không tràn ring buffer; test queue full, malformed command và timeout.
- `STM-REQ-04`: driver GPIO bảo toàn bit pin khác, reject pin/config sai, startup safe state. Host fake-register test kiểm địa chỉ/mask/sequence; board test kiểm pad.
- `STM-REQ-05`: DMA buffer không mất dữ liệu khi cache bật; đánh dấu **pending** nếu chưa có thiết bị và measurement thích hợp.

**Tool:** STM32CubeIDE/CubeMX để build/debug, ST-LINK/SWD và GDB trên board, host GCC/Clang cho unit, oscilloscope/logic analyzer cho timing. TRACE32 chỉ khi có probe/license và mục tiêu debug nâng cao. Bắt đầu từ example vendor để xác nhận toolchain, sau đó viết driver để hiểu register; HAL/LL dùng để đối chiếu, không trộn quyền sở hữu cùng peripheral.

**Câu hỏi tự kiểm trước code:** `BSRR` khác RMW `ODR` thế nào? Vì sao NVIC priority khác task priority? CPU đọc được buffer DMA có nghĩa dữ liệu cache đã coherent chưa? Reset handler làm gì trước `main()`? Trả lời bằng RM/PM và schematic, rồi mới mở lab.
